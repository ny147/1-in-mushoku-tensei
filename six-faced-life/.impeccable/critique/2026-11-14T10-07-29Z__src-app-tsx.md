## What's working

- Four labeled navigation destinations and a distinct active state keep the main structure understandable.
- Character headings, stats and numerical values fit the tested 390px phone layout without document-level horizontal overflow.
- The phone menu opens; Escape closes it and its expanded state returns to false. Existing heading focus and native disclosures provide a useful foundation.

## Priority issues

### P1: Section navigation has no browser history or actionable return trail

`App.tsx:116,322,491`: `navigate()` changes React state without URL/history integration. The breadcrumb is a `span` and `strong`; `Brand()` at line 86 returns a `div`. Reproduction: Character -> World -> browser Back returned to `about:blank`, rather than Character. The URL stayed `/` across section changes. Reload initializes the chronicle/new-life screen rather than the section being read.

Why it matters: the player loses their place and expected return controls do nothing. This is a navigation failure, not evidence of lost life data.

Fix: use URL-backed destinations with Back/Forward handling and safe reload restoration. Make the logo return to the current life's chronicle (or new-life setup when no life exists). Use a semantic breadcrumb whose ancestor is a real link and whose current item has `aria-current="page"`. Returning from an archive preview should restore the archive list. Preserve pending choices, pause behavior, focus, and saved progress; navigation must never undo simulation actions.

Suggested command: `/impeccable harden app navigation`.

### P1: Fixed sidebar puts Help below an unscrollable short viewport

`styles.css:241,385`, `App.tsx:473`: the fixed full-height sidebar has no vertical scrolling. With an actual CSS viewport of 800 x 545 and the ordinary two-line name Mira Ashvale, Help occupied y684-725 while the viewport ended at y545. The sidebar bottom extended to y888. Scrolling the main document does not give this fixed sidebar an internal scroll range.

Why it matters: a player on a short laptop window or enlarged browser view cannot reach Help with a pointer.

Fix: make sidebar content vertically scrollable with bounded flex sizing, keep navigation/help reachable, and compact optional identity/colophon content at short heights. Verify pointer and keyboard reachability, long names and enlarged text.

Suggested command: `/impeccable adapt sidebar for short windows`.

### P2: Brand title crosses the sidebar boundary

`styles.css:252-280,2376-2395`: the title is nowrap, while the tablet sidebar narrows to 184px. At an actual 800px CSS viewport the sidebar ended at x184 and the title ended at x191. Its brand container ended at x172, so it also invaded the reserved inner spacing.

Why it matters: this reproduces the basic alignment mismatch in the supplied screenshot and makes the shell appear unfinished.

Fix: give the text flexible width with `min-width: 0`, preserve the icon's size, and allow an intentional two-line title or a tested compact title at the tablet breakpoint. Do not hide the overflow or squeeze the whole application to conceal it. Check EN/TH and every sidebar breakpoint.

Suggested command: `/impeccable layout sidebar brand`.

## Minor observations and questions to consider

- The screenshot's much larger apparent content offset was not reproduced. In the tested tablet state, content began at x209 after the x184 sidebar. Do not claim a whole-page horizontal overflow bug from the crop alone.

- What should an archive preview's return destination preserve: list position and selected life? Recommend both.
- Should refreshing a character/world view restore that section? Recommend yes, while playback remains paused.
